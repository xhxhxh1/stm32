## 知识点速查

| 知识点 | 做题时怎么判断 |
| --- | --- |
| 嵌入式系统 | 以应用为中心，面向特定功能，软硬件可裁剪。常见要求有实时性、可靠性、体积、成本和功耗 |
| ARM、Cortex-M3、STM32 | ARM 提供内核设计。Cortex-M3 是 32 位处理器内核。STM32F103 则是在芯片中集成了该内核、存储器和外设的微控制器 |
| Cortex-M3 架构 | 属于 ARMv7-M，采用改进型哈佛架构，取指和数据使用不同的总线接口。三级流水线是**取指、译码、执行** |
| 4 GB 地址空间 | 32 位地址可表示 `2³²` 个字节地址，范围是 `0x00000000～0xFFFFFFFF`。芯片实际装有的 Flash、SRAM 容量应按型号读 |
| 裸机与操作系统 | 裸机例程通常初始化后进入主循环，也可以响应中断。带操作系统时，软件由设备驱动、操作系统和应用等部分组成 |

架构及流水线可对照 [Arm Cortex-M3 内核说明](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/a-tour-of-the-cortex-m3-core)。

## 题型练习

1. **单选**　Cortex-M3 的三级流水线按什么顺序执行？

   A. 译码、取指、执行　B. 取指、译码、执行　C. 取指、执行、译码

2. **多选**　哪些是嵌入式系统常见的设计要求？

   A. 控制功耗　B. 满足实时响应期限　C. 按任务裁剪软硬件　D. 通用计算性能必须最高

3. **判断**　没有操作系统的 STM32 程序也可以使用外部中断。

<details>

<summary>展开答案与理由</summary>

1. **B。** 先取出指令，再译码，最后执行。
2. **ABC。** 资源按产品的功能和约束配置。
3. **对。** 裸机程序可由 NVIC 和异常机制进入中断服务函数。

</details>

### 1.1 嵌入式系统概述

<details>

<summary>展开本节详解</summary>

计算机的发展既包括用于通用计算、海量存储的通用计算机，也包括嵌入各种装置、负责特定运算和控制的嵌入式系统。判断一个系统是不是嵌入式系统，要看它在产品中的用途与约束。

#### 1.1.1 什么是嵌入式系统

**【重点·定义】** 以应用为核心、以计算机技术为基础，软硬件可裁剪，适应应用系统对功能、可靠性、安全性、成本、体积、重量、功耗、环境等严格要求的专用计算机系统。

- “应用为核心”：先确定产品要完成的任务，再选择芯片、存储器和软件。
- “专用”：围绕确定的功能设计，例如洗衣机控制、温度检测。
- “可裁剪”：硬件和软件都可以按需求取舍，不必追求配置越高越好。
- “严格要求”：例如电池产品重视功耗，控制设备重视响应时间和可靠性。

**SCM、MCU要会区分名称。** SCM指单片微型计算机，常简称单片机；MCU指微控制器。单片机把微型计算机的主要功能部件集成在一片芯片上。课件以8位单片机和基于ARM的32位单片机介绍不同层次的嵌入式系统。

**【基础补充】CPU、MCU和开发板不是一个层次。** CPU内核负责执行指令；MCU把内核、存储器和外设集成成芯片；开发板在MCU之外接上电源、晶振、按键、LED和接口，使芯片方便使用。

#### 1.1.2 嵌入式系统和通用计算机比较

二者都是硬件和软件的集合。

| 比较项 | 嵌入式系统 | 通用计算机 |
| --- | --- | --- |
| 存在形态 | 嵌入设备和产品，形态随应用变化 | 常以标准化计算设备独立存在 |
| 主要用途 | 完成特定监测、运算、控制任务 | 运行多类应用，处理通用任务 |
| 价值体现 | 产品功能和使用效果 | 通用计算能力、存储能力等 |
| 资源选择 | 满足需求并控制成本、功耗 | 通常强调通用性和扩展能力 |
| 功耗 | 课件以mW～W量级举例 | 课件以较高功耗的桌面设备作对比 |

**【易错点】** 功耗数值是课件用于说明差异的例子，不是分类的硬性界线；有屏幕、能联网或能运行操作系统，都不能单独决定它是不是嵌入式系统。

#### 1.1.3 嵌入式系统特点

| 特点 | 应理解的含义 | 答题例子 |
| --- | --- | --- |
| 专用性强 | 围绕特定设备和任务设计 | 微波炉控制程序不能直接当作洗衣机控制程序 |
| 可裁剪性 | 按需选取软硬件功能 | 选择所需外设、驱动和软件模块 |
| 实时性好 | 在任务要求的时间内响应 | ATM插卡后及时启动读卡 |
| 可靠性高 | 要求持续、稳定运行 | 看门狗、内存保护、重启等机制 |
| 生命周期长 | 与具体产品生命周期相联系 | 导入、成长、成熟、衰退阶段 |
| 不易被垄断 | 应用差异大，技术与产品形式多样 | 不同产品采用不同软硬件方案 |

**【基础补充·实时性】** “实时”强调在规定期限内完成，不等于“运行速度绝对最快”。一个结果算得正确，但错过控制时机，也可能不满足任务要求。

#### 1.1.4 嵌入式系统的应用领域

掌握分类并能举例：工业控制中的工控设备、智能仪表和汽车电子；军事国防中的军事电子；消费电子中的信息家电、智能玩具、通信设备和移动存储；网络领域中的网络设备和电子商务设备。

#### 1.1.5 嵌入式系统范例

课件案例为“幼儿算术学习机”和“智盘，快速结账系统”。复习时用“输入信息→处理→输出结果”说明嵌入式系统在产品中的作用即可，不需要推测课件没有介绍的内部算法。

</details>

### 1.2 ARM Cortex-M3 处理器

<details>

<summary>展开本节详解</summary>

#### 1.2.1 ARM简介

**【重点】** ARM是Advanced RISC Machine。课件中ARM既指公司，也用于描述处理器架构及采用该架构的处理器。RISC是精简指令集。

- 课件强调ARM技术的低成本、高性能、低功耗。
- 课件介绍的商业模式是ARM提供处理器IP核，由芯片厂商设计完整的微控制器产品。
- **IP核不是一块可以直接接电运行的开发板。** 在本课程的链条中，ARM提供Cortex-M3内核设计，ST基于它设计STM32F103微控制器。

**【基础补充】“32位”主要描述处理器的数据处理和寄存器宽度等架构特征，不表示只有32个引脚，也不等于32KB存储器。**

#### 1.2.2 ARM处理器

课件介绍ARM7、ARM9、ARM11到Cortex系列的发展，并比较处理器名称、架构版本和存储器管理特性。

| 名称/术语 | 复习要点 |
| --- | --- |
| Cortex-M3 | 本课程内核；表中对应v7-M；带NVIC，MPU可选 |
| Cortex-R系列 | 课件产品表中的另一类Cortex处理器，不等同于M3 |
| Cortex-A系列 | 课件产品表中的另一类Cortex处理器，不等同于M3 |
| MMU | 存储器管理单元，注意与MPU区分 |
| MPU | 存储器保护单元，强调访问保护 |
| NVIC | 嵌套向量中断控制器，第8章重点学习 |

**【易错点】** “Cortex-M3”是内核名称，“ARMv7-M”是架构版本，“STM32F103ZET6”是具体芯片型号，三者不能互换。

</details>

### 1.3 STM32微控制器

<details>

<summary>展开本节详解</summary>

#### 1.3.1 从Cortex-M3内核到基于Cortex-M3的MCU

完整MCU由内核以及存储器、时钟与复位、I/O、外设和调试等部分组成。本课程后续学习的GPIO、定时器等，是使用MCU外围功能；NVIC和SysTick则与Cortex-M3内核紧密相关。

**【基础补充·最常见的存储器区别】**

| 名称 | 主要用途 | 断电后 |
| --- | --- | --- |
| Flash | 存放程序及需要长期保存的数据 | 可以保留内容 |
| SRAM | 存放运行中的变量、栈等 | 通常丢失内容 |
| 外设寄存器 | 控制外设或读取其状态 | 状态受复位和硬件行为影响 |

程序中的`GPIOC->ODR`访问的是GPIO外设寄存器，不能按普通数组变量的行为随意推断所有寄存器的读写方式。

#### 1.3.2 微控制器产品线

STM32包含多个产品系列，同一系列还可能有不同容量、封装和外设配置。本课程围绕STM32F103ZET6展开，后续的引脚数量、存储器大小、定时器分布等都应在这个型号范围内理解。

#### 1.3.3 STM32微控器命名规则

**【重点·必须会拆读】STM32 F 103 Z E T 6。**

| 字段 | 本型号含义 |
| --- | --- |
| STM32 | STM32产品系列 |
| F | 通用类型 |
| 103 | 增强型子系列 |
| Z | 144引脚 |
| E | 512KB Flash |
| T | LQFP封装 |
| 6 | 工业级温度范围−40℃～85℃ |

课件还列出引脚代码T=36、C=48、R=64、V=100、Z=144；Flash容量代码4=16KB、6=32KB、8=64KB、B=128KB、C=256KB、D=384KB、E=512KB。

**【易错点】** 字母必须放在字段位置上理解：引脚数字段中的T与封装字段中的T，含义不同。型号中的E表示Flash容量，不能由此直接得出SRAM容量。

**【基础补充·单位】** 1字节=8位；本课程存储容量按1KB=1024字节理解。512KB=524288字节，64KB=65536字节。72MHz表示每秒7200万个时钟周期，不表示每条C语句都能在一个周期完成。

$$
T_{clk}=\frac{1}{f_{clk}}=\frac{1}{72\times10^6}\ \mathrm{s}\approx13.89\ \mathrm{ns}
$$

</details>

### 1.4 嵌入式系统的软件

<details>

<summary>展开本节详解</summary>

软件是实现设备功能的控制核心。按体系结构分为无操作系统和带操作系统两种。

#### 1.4.1 无操作系统的嵌入式软件

**【重点】** 引导/启动程序在上电后先运行，负责必要的初始化；应用程序随后运行，直接使用硬件及驱动完成任务。课件中引导程序通常用汇编，应用程序通常用C语言。

**【基础补充·主循环结构】** 下面是结构示意，函数名表示任务，不是课件提供的完整可编译程序：

```c
int main(void)
{
    Hardware_Init();       /* 初始化时钟、GPIO等 */
    while (1)
    {
        Read_Inputs();    /* 读取按键等输入 */
        Process_Task();   /* 处理业务逻辑 */
        Update_Outputs(); /* 更新显示、LED等输出 */
    }
}
```

`while (1)`表示程序持续运行。使用中断并不意味着使用了操作系统；裸机程序同样可以响应中断。

#### 1.4.2 带操作系统的嵌入式软件

课件自下而上的层次为设备驱动层、操作系统层、应用软件层。应用通过操作系统提供的机制组织任务，便于复杂功能的开发、移植和扩展，同时也需要额外的代码、内存和运行资源。

#### 1.4.3 典型嵌入式操作系统

| 系统 | 课件中的认识重点 |
| --- | --- |
| μC/OS-II | 可裁剪、可移植、抢占式实时多任务内核 |
| VxWorks | 嵌入式实时操作系统 |
| 嵌入式Linux | 对Linux进行裁剪修改，用于嵌入式系统 |
| Android | 基于Linux，主要用于移动设备 |
| Windows CE | 课件列举的32位嵌入式操作系统，支持多任务、多线程 |

这些是课件列举的软件类型，不表示本课程芯片能够直接运行表中所有系统。

#### 1.4.4 软件架构选择建议

选择时考虑功能复杂度、硬件资源、实时要求和开发者经验。简单控制任务通常可以采用主循环加中断；任务较复杂时再考虑合适的操作系统。课件建议本课程常规STM32实验采用无操作系统方式。

**【易错点】** 32位MCU不等于必须安装操作系统；带操作系统也不自动保证程序正确或实时性达标。

</details>
